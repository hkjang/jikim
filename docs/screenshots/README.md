# 화면 캡처 갤러리 계약

이 폴더에는 홍보 페이지와 사용자 가이드에 사용할 **실제 릴리스 후보 화면**만 둡니다. 아직 캡처하지 않은 화면을 제품 화면처럼 보이는 합성 이미지로 대체하지 않습니다.

현재 [`manifest.json`](manifest.json)은 v0.2.0을 대상으로 하며 `status`는 `complete`입니다. `jikim:v0.2.0` 이미지와 전용 PostgreSQL을 기동한 Playwright 검증에서 모든 필수 데스크톱·모바일 화면을 다시 캡처했습니다.

릴리스 게이트는 빌드한 `jikim:v0.2.0` 이미지와 전용 PostgreSQL을 Docker 내부 네트워크에서 기동한 다음 `scripts/e2e-docker.sh`로 Playwright 전체 화면 검증과 캡처를 수행합니다. 캡처 조건은 다음과 같습니다.

- 데스크톱: 1440×1024, 브라우저 확대 100%
- 모바일: 390×844, 모바일 접미사는 `-mobile.png`
- 언어: 한국어
- 테마: 기본 밝은 테마
- Secret 값, 토큰, DSN, Client Secret, 이메일 등 민감정보는 fixture 값이라도 마스킹
- 로그인 이후 화면은 전용 데모 계정과 비운영 데이터만 사용
- 화면별 파일명과 필요한 역할은 `manifest.json`을 기준으로 고정
- `generated_at`은 UTC RFC 3339로 기록

## 릴리스 게이트

1. `manifest.json`의 `version`과 E2E의 `E2E_VERSION`이 릴리스 버전과 같아야 합니다.
2. `manifest.json`에서 `required: true`인 모든 데스크톱 파일이 존재해야 합니다.
3. `mobile_required: true`인 로그인, 대시보드, Secret 목록, 개인 키, 관리자 설정은 모바일 캡처도 필요합니다.
4. 브라우저 콘솔 오류와 실패한 네트워크 요청이 없어야 합니다.
5. 로그인 화면과 프로필 메뉴에 동일한 서비스 버전이 보여야 합니다.
6. 새로고침 후 현재 URL의 메뉴와 화면이 유지되어야 합니다.
7. 관리자 사용자 메뉴의 스크롤바가 메뉴 경계를 벗어나지 않아야 합니다.
8. 모든 조건을 통과하고 새 PNG가 생성된 뒤에만 `generated_at`을 기록하고 `status`를 `complete`로 변경합니다.

캡처 파일은 Playwright 결과와 갤러리 계약을 일치시키기 위해 PNG를 사용합니다. 민감정보가 없는지 확인한 뒤 저장소 크기가 과도해지지 않도록 최적화합니다. 새 릴리스에서 화면이 바뀌면 먼저 `capture-required`로 되돌리고 동일한 검증을 다시 수행합니다.
