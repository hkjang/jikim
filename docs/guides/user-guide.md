# 사용자 가이드

jikim의 기본 화면과 개인 키, Secret, 승인 흐름을 설명합니다. 메뉴와 버튼은 한국어를 기본으로 합니다.

## 로그인

1. 서비스의 `/login`으로 이동합니다.
2. 관리자가 제공한 로컬 계정으로 로그인하거나, 활성화된 경우 **Keycloak SSO로 로그인**을 선택합니다.
3. 로그인 화면 하단에서 서비스 버전을 확인합니다.

비밀번호나 SSO 인증 정보는 jikim 운영자에게도 전달하지 마십시오. 인증 실패가 반복되면 브라우저 주소와 발생 시각만 관리자에게 전달합니다.

## 메뉴와 URL

각 주요 메뉴는 고유 URL을 사용합니다. 브라우저 새로고침이나 주소 공유 후에도 권한이 있는 동일 화면이 다시 열려야 합니다. 접근 권한이 없으면 빈 화면이 아니라 권한 안내 화면으로 이동합니다.

- 대시보드: 보안 상태와 최근 활동
- Secret: 목록, 상세, 버전과 편집
- 애플리케이션: 서비스와 Secret 관계
- 승인: 내 요청 및 검토할 요청
- 감사: 권한이 있는 사용자의 이벤트 조회
- 개인화: 프로필과 개인 키
- 서비스 관리: 관리자 전용 설정

상단 프로필 메뉴에서도 현재 서비스 버전을 확인할 수 있습니다.

## Secret 찾기와 보기

1. **Secret → Secret Explorer**로 이동합니다.
2. 경로, 애플리케이션, 환경, Owner 또는 태그로 검색합니다.
3. 상세 화면에서 메타데이터와 현재 버전을 확인합니다.
4. 값 표시가 필요한 경우에만 명시적으로 표시하고 사용 후 즉시 다시 마스킹합니다.

Secret 값은 메신저, 이슈, 스크린샷 또는 셸 히스토리에 붙여 넣지 않습니다. 목록 조회 권한과 값 복호화 권한은 다를 수 있습니다.

## 생성과 변경

입력 전에 경로, Owner, 애플리케이션, 환경과 설명을 확인합니다. 운영 Secret에는 의미 있는 Owner와 회전 기준을 지정합니다.

- 승인 워크플로가 꺼져 있으면 권한 검증 후 바로 반영됩니다.
- 관리자가 대상 작업에 워크플로를 켰으면 변경 대신 승인 요청이 만들어집니다.
- 반려된 요청은 사유를 확인하고 새 요청으로 다시 제출합니다.

v0.1.0의 Secret 제출 화면에는 요청 사유 입력란이 없습니다. 검토자는 요청자·작업·대상 경로를 확인하고 승인 또는 반려할 때 검토 의견을 남깁니다.

## 개인 키 관리

**프로필 → 개인 키**에서 현재 버전, 권한, 최근 회전 시각을 확인합니다.

회전 전에는 다음을 확인합니다.

1. 이전 키 버전을 사용하는 데이터가 있는지
2. 회전 권한이 있는지
3. 작업 중인 다른 회전 요청이 없는지

회전 후 새 버전과 감사 이벤트를 확인합니다. 오류가 나면 반복 실행하기 전에 관리자에게 요청 ID와 시각을 전달합니다.

## 팀장 검토

`manager` 권한이 있고 워크플로가 활성화된 경우 승인 메뉴에서 요청을 검토합니다.

- 요청자 ID와 대상 경로, 작업 확인
- 요청자가 현재도 해당 Secret 작업 권한을 보유하는지 확인
- Secret 값 자체가 아닌 변경 목적과 정책 적합성 검토
- 승인 또는 반려 시 근거 기록

자신이 만든 요청은 승인할 수 없습니다. v0.1.0은 Break Glass를 제공하지 않으므로 긴급 상황에서도 별도의 조직 운영 절차 없이 승인 흐름을 우회하지 마십시오.

## 오류가 보일 때

- `401`: 세션 만료 가능성이 있으므로 다시 로그인
- `403`: 정책 또는 역할이 부족함
- `404`: 삭제되었거나 권한 때문에 보이지 않는 리소스일 수 있음
- `409`: 같은 경로나 중복 작업이 이미 존재함
- `5xx`: 요청 ID, 시각, 메뉴 이름을 기록하고 관리자에게 전달

화면에 Secret 평문이 보였다면 오류 보고 스크린샷을 찍기 전에 반드시 마스킹하십시오.
