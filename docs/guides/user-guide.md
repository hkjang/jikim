# 사용자 가이드

jikim의 기본 화면과 개인 키, Secret, 승인 흐름을 설명합니다. 메뉴와 버튼은 한국어를 기본으로 합니다.

## 로그인

1. 서비스의 `/login`으로 이동합니다.
2. 관리자가 제공한 로컬 계정으로 로그인하거나, 활성화된 경우 **Keycloak SSO로 로그인**을 선택합니다.
3. 로그인 화면 하단에서 서비스 버전을 확인합니다.

비밀번호나 SSO 인증 정보는 jikim 운영자에게도 전달하지 마십시오. 인증 실패가 반복되면 브라우저 주소와 발생 시각만 관리자에게 전달합니다.

SSO 로그인 후에는 같은 서비스 Origin의 `/oidc/callback`을 거쳐 자동으로 로그인 화면이 전환됩니다. 주소에 짧은 일회용 `code`가 잠시 보일 수 있으나 세션 토큰은 URL이나 응답 화면에 노출되지 않고 HttpOnly 쿠키로 설정됩니다. callback URL을 복사·공유하거나 다른 Origin으로 바꾸지 마십시오.

## 메뉴와 URL

각 주요 메뉴는 고유 URL을 사용합니다. 브라우저 새로고침이나 주소 공유 후에도 권한이 있는 동일 화면이 다시 열려야 합니다. 접근 권한이 없으면 빈 화면이 아니라 권한 안내 화면으로 이동합니다.

- 대시보드: 보안 상태와 최근 활동
- Secret: 목록, 상세, 버전과 편집
- 애플리케이션: 서비스와 Secret 관계
- 승인: 내 요청 및 검토할 요청
- 감사: 권한이 있는 사용자의 이벤트 조회
- 개인화: 프로필과 개인 키
- 서비스 관리: 관리자 전용 설정

상단 프로필 메뉴에서도 현재 서비스 버전을 확인할 수 있습니다.

## Secret 찾기와 보기

1. **Secret → Secret Explorer**로 이동합니다.
2. 경로, 애플리케이션, 환경, Owner 또는 태그로 검색합니다.
3. 상세 화면에서 메타데이터와 현재 버전을 확인합니다.
4. 값 표시가 필요한 경우에만 명시적으로 표시하고 사용 후 즉시 다시 마스킹합니다.

Secret 값은 메신저, 이슈, 스크린샷 또는 셸 히스토리에 붙여 넣지 않습니다. 목록 조회 권한과 값 복호화 권한은 다를 수 있습니다.

Secret 생성·변경·회전·삭제 또는 승인 결과는 관리자가 활성화한 경우 서명 Webhook 운영 이벤트를 발생시킬 수 있습니다. 이벤트에는 대상 경로, 요청 ID, 버전 같은 메타데이터만 포함되며 Secret 평문은 전달하지 않습니다.

## 생성과 변경

입력 전에 경로, Owner, 애플리케이션, 환경과 설명을 확인합니다. 운영 Secret에는 의미 있는 Owner와 회전 기준을 지정합니다.

- 승인 워크플로가 꺼져 있으면 권한 검증 후 바로 반영됩니다.
- 관리자가 대상 작업에 워크플로를 켰으면 변경 대신 승인 요청이 만들어집니다.
- 반려된 요청은 사유를 확인하고 새 요청으로 다시 제출합니다.

v0.2.0의 Secret 제출 화면에는 요청 사유 입력란이 없습니다. 검토자는 요청자·작업·대상 경로를 확인하고 승인 또는 반려할 때 검토 의견을 남깁니다.

## 개인 키 관리

**프로필 → 개인 키**에서 현재 버전, 권한, 최근 회전 시각을 확인합니다.

회전 전에는 다음을 확인합니다.

1. 이전 키 버전을 사용하는 데이터가 있는지
2. 회전 권한이 있는지
3. 작업 중인 다른 회전 요청이 없는지

회전 후 새 버전과 감사 이벤트를 확인합니다. 오류가 나면 반복 실행하기 전에 관리자에게 요청 ID와 시각을 전달합니다.

## 팀장 검토

`manager` 권한이 있고 워크플로가 활성화된 경우 승인 메뉴에서 요청을 검토합니다.

- 요청자 ID와 대상 경로, 작업 확인
- 요청자가 현재도 해당 Secret 작업 권한을 보유하는지 확인
- Secret 값 자체가 아닌 변경 목적과 정책 적합성 검토
- 승인 또는 반려 시 근거 기록

자신이 만든 요청은 승인할 수 없습니다. v0.2.0은 Break Glass를 제공하지 않으므로 긴급 상황에서도 별도의 조직 운영 절차 없이 승인 흐름을 우회하지 마십시오.

## AI 보안 도우미

관리자가 AI 연동을 활성화하면 **AI 보안 도우미**에서 메타데이터와 보안 집계를 바탕으로 분석 초안을 받을 수 있습니다. 응답은 SSE 스트리밍으로 표시되며 **응답 중지**를 누르면 현재 요청이 취소됩니다.

- 비밀번호, API Key, 세션 토큰, 개인 키, DSN처럼 Secret 평문으로 보이는 입력은 서버가 거부합니다.
- 브라우저가 별도 `context`를 보내더라도 Upstream에는 전달되지 않습니다. 역할에 맞춘 서버 집계만 컨텍스트로 사용합니다.
- `max_tokens`는 관리자 상한과 262144 중 더 낮은 값으로 제한됩니다.
- 사용자별 분당 30회, 동시 2개 요청 제한이 있습니다. 초과 시 `429`가 표시되므로 기존 스트림을 종료하고 60초 후 다시 시도합니다.
- AI 답변은 정책 적용이나 승인 결과가 아니라 검토용 초안입니다. 실제 변경 전 정책 시뮬레이션과 담당자 확인을 거칩니다.

Upstream 장애, SSE가 아닌 응답 또는 설정 비활성 상태에서는 일반 오류 안내가 표시됩니다. 입력을 반복 전송하지 말고 요청 ID와 발생 시각을 관리자에게 전달하십시오.

## 오류가 보일 때

- `401`: 세션 만료 가능성이 있으므로 다시 로그인
- `403`: 정책 또는 역할이 부족함
- `404`: 삭제되었거나 권한 때문에 보이지 않는 리소스일 수 있음
- `409`: 같은 경로나 중복 작업이 이미 존재함
- `429`: 로그인 또는 AI 요청 제한에 도달함. `Retry-After` 이후 재시도
- `5xx`: 요청 ID, 시각, 메뉴 이름을 기록하고 관리자에게 전달

화면에 Secret 평문이 보였다면 오류 보고 스크린샷을 찍기 전에 반드시 마스킹하십시오.
